# 🌐 Тестирование без локального запуска

## 🚀 Ваш проект уже задеплоен!

Поскольку у вас нет возможности запустить проект локально (Node.js не установлен), давайте протестируем функциональность создания событий через уже работающую версию.

## 🔗 Ссылки для тестирования

### Production URL (Vercel)
Ваш проект автоматически деплоится на Vercel после каждого push в GitHub.

**URL проекта**: `https://calendly-mvp.vercel.app` (или ваш конкретный Vercel URL)

## 📋 Пошаговое тестирование

### Шаг 1: Откройте проект в браузере
1. Перейдите на ваш Vercel URL
2. Проект должен загрузиться

### Шаг 2: Войдите в систему
1. Нажмите "Login" или перейдите на `/login`
2. Используйте ваши Supabase учетные данные
3. Или зарегистрируйтесь через `/register`

### Шаг 3: Перейдите к созданию событий
1. После входа перейдите на `/dashboard/event-types`
2. Нажмите "Создать событие"
3. Или сразу откройте `/dashboard/event-types/new`

### Шаг 4: Протестируйте диагностику
1. На странице создания события найдите секцию "🔧 Диагностика"
2. Нажмите "Проверить подключение к Supabase"
3. Посмотрите результаты в журнале

### Шаг 5: Создайте событие
1. Заполните форму:
   - **Название**: "Тестовая встреча"
   - **Описание**: "Проверка функциональности"
   - **Длительность**: "30 минут"
   - **Место**: "Zoom встреча"
2. Нажмите "Создать событие"
3. Следите за журналом выполнения справа

## ⚙️ Настройка переменных окружения

### В Vercel Dashboard:
1. Откройте https://vercel.com/dashboard
2. Найдите ваш проект
3. Перейдите в "Settings" → "Environment Variables"
4. Добавьте:
   ```
   NEXT_PUBLIC_SUPABASE_URL = ваш_supabase_url
   NEXT_PUBLIC_SUPABASE_ANON_KEY = ваш_supabase_key
   ```

### В GitHub Codespaces:
1. Создайте файл `.env.local` в корне
2. Добавьте переменные окружения
3. Перезапустите сервер

### ⚠️ Возможные проблемы на production:

#### "Invalid API key"
**Причина**: Не настроены переменные окружения в Vercel
**Решение**: Добавьте ключи в Vercel Dashboard → Settings → Environment Variables

#### "User not authenticated"
**Причина**: Проблемы с аутентификацией Supabase
**Решение**: Проверьте настройки аутентификации в Supabase Dashboard

#### "Table doesn't exist"
**Причина**: Миграции не применены
**Решение**: Примените миграции в Supabase Dashboard → SQL Editor
